= 7. Windows Updates

The `win_updates` module checks for or installs Windows updates through the Windows Update service on the host. This lab's Windows server is configured to use Microsoft Update, so the job can search for and install updates directly.

You can limit the install to categories such as security updates, and you can choose whether Ansible reboots the host when an update requires it.

[#create-the-playbook]
== ☑️ Creating the playbook

In Visual Studio Code, open the Explorer view and find the *WORKSHOP_PROJECT* section where you created `iis_basic`.

. Hover over *WORKSHOP_PROJECT* and click *New Folder*. Name the folder `win_updates`.
. Right-click `win_updates`, select *New File*, and name it `site.yml`.

image::7-create-win_updates.png[Empty site.yml,link=self,window=_blank]

Edit `site.yml` and add the following:

[source,yaml]
----
---
- name: This is my Windows patching playbook
  hosts: windows
  tasks:
    - name: Install Windows Updates
      ansible.windows.win_updates:
        category_names: "{{ categories | default(omit) }}"
        reboot: "{{ reboot_server | default(true) }}"
----

image::7-win_update-playbook.png[Windows updates playbook,link=self,window=_blank]

[NOTE]
====
* `win_updates` checks for updates and installs the ones you select.
* `category_names` limits the install to the categories passed in by the job template survey. When the survey does not provide a value, the module's own default is used.
* `reboot` reboots the host when an update requires it and continues the install afterward. The survey controls this value.
====

[#run-the-playbook]
== ☑️ Running the playbook

. Open *Templates*.
. Launch *Windows Updates*.
. Leave the default categories selected, or choose your own.
. Choose *Yes* for *Reboot after install?*
. Click *Next*, then *Launch*.

The job log updates while the host is patched. A cumulative update can take several minutes. If a reboot is required, the job waits for Windows to come back and then finishes the install.

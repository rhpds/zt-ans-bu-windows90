= 8. Chocolatey

Chocolatey is a package manager for Windows. The `chocolatey.chocolatey` collection lets Ansible install, update, and configure packages on a Windows host. The collection is already available in the *Windows Workshop Execution Environment*, and the Chocolatey client is already installed on the Windows host.

[#install-packages]
== ☑️ Installing specific versions

An ad-hoc command is useful for one package. A playbook is a better fit when you want several packages at specific versions.

In Visual Studio Code, under *WORKSHOP_PROJECT*, create a folder named `chocolatey` and a file named `install_packages.yml`.

image::8-chocolatey-empty-install_packages-editor.png[Empty install_packages.yml,link=self,window=_blank]

Add this playbook:

[source,yaml]
----
---
- name: Install specific versions of packages using Chocolatey
  hosts: windows
  gather_facts: false
  vars:
    choco_packages:
      - name: nodejs
        version: 13.0.0
      - name: python
        version: 3.6.0
  tasks:
    - name: Remove Node.js and Python so an older version can be installed
      chocolatey.chocolatey.win_chocolatey:
        name: "{{ item }}"
        state: absent
      loop:
        - nodejs
        - nodejs.install
        - python
        - python3

    - name: Install specific versions of packages sequentially
      chocolatey.chocolatey.win_chocolatey:
        name: "{{ item.name }}"
        version: "{{ item.version }}"
        force: true
      loop: "{{ choco_packages }}"

    - name: Check python version
      ansible.windows.win_command: python --version
      register: check_python_version

    - name: Check nodejs version
      ansible.windows.win_command: node --version
      register: check_node_version

    - name: Show installed versions
      ansible.builtin.debug:
        msg: Python version is {{ check_python_version.stdout_lines[0] }} and Node.js version is {{ check_node_version.stdout_lines[0] }}
----

[NOTE]
====
`gather_facts` is disabled because this play does not use the discovered host facts. The first task removes any existing Python and Node.js packages. This will be skipped in this run, but a later exercise runs this job again after the packages have been installed and updated. The `win_command` tasks record the installed versions, and the debug task prints them.
====

....

[#update-packages]
== ☑️ Updating packages

`win_chocolatey` also removes and updates packages. The `state` value selects the action:

* `present` ensures the package is installed. This is the default.
* `absent` ensures the package is not installed.
* `latest` ensures the package is installed at the newest available version.

The previous playbook installed older versions on purpose. This playbook updates every package Chocolatey has installed by setting `name` to `all` and `state` to `latest`.

Create `chocolatey/update_packages.yml`:

[source,yaml]
----
---
- name: Update all packages using Chocolatey
  hosts: windows
  gather_facts: false
  tasks:
    - name: Update all installed packages
      chocolatey.chocolatey.win_chocolatey:
        name: all
        state: latest

    - name: Check python version
      ansible.windows.win_command: python --version
      register: check_python_version

    - name: Check nodejs version
      ansible.windows.win_command: node --version
      register: check_node_version

    - name: Show installed versions
      ansible.builtin.debug:
        msg: Python version is {{ check_python_version.stdout_lines[0] }} and Node.js version is {{ check_node_version.stdout_lines[0] }}
----

Commit and push the file, then sync the project.

You can copy the install template instead of starting from a blank form. On *Templates*, click the kebab menu and select *Duplicate template*, then edit the copy.

[#chocolatey-facts]
== ☑️ Gathering Chocolatey facts

`win_chocolatey_facts` collects the client configuration, features, sources, and installed packages. Create `chocolatey/chocolatey_configuration.yml`:

[source,yaml]
----
---
- name: Chocolatey facts and configuration
  hosts: windows
  gather_facts: false
  tasks:
    - name: Gather facts from Chocolatey
      chocolatey.chocolatey.win_chocolatey_facts:

    - name: Display the gathered facts
      ansible.builtin.debug:
        var: ansible_chocolatey
----

The facts are stored in `ansible_chocolatey`. Commit, push, and sync the project, then create the following job template.

Launch it and scroll through `ansible_chocolatey`. You should see `git`, `nodejs`, and `python` in the package list, along with the community source those packages came from.

image::8-chocolatey-configuration-job-run-1-successful.png[Chocolatey facts output,link=self,window=_blank]

Individual values are keys in that object. `ansible_chocolatey.packages` is the list of installed packages, which is what you would use to build a report.

[#configure-chocolatey]
== ☑️ Configuring Chocolatey

`win_chocolatey_config` changes Chocolatey settings. The facts from the previous run show the defaults: `cacheLocation` is empty, and `commandExecutionTimeoutSeconds` is `2700`. This step sets the cache directory to `C:\ChocoCache` and the timeout to `3600` seconds.

Add these tasks to `chocolatey_configuration.yml`, after the task that displays `ansible_chocolatey`:

[source,yaml]
----
    - name: Create a directory for the Chocolatey cache
      ansible.windows.win_file:
        path: C:\ChocoCache
        state: directory

    - name: Configure Chocolatey to use the new cache directory
      chocolatey.chocolatey.win_chocolatey_config:
        name: cacheLocation
        state: present
        value: C:\ChocoCache

    - name: Change the execution timeout
      chocolatey.chocolatey.win_chocolatey_config:
        name: commandExecutionTimeoutSeconds
        state: present
        value: 3600

    - name: Gather facts after reconfiguring Chocolatey
      chocolatey.chocolatey.win_chocolatey_facts:

    - name: Display the new configuration
      ansible.builtin.debug:
        var: ansible_chocolatey.config
----

The finished playbook is:

[source,yaml]
----
---
- name: Chocolatey facts and configuration
  hosts: windows
  gather_facts: false
  tasks:
    - name: Gather facts from Chocolatey
      chocolatey.chocolatey.win_chocolatey_facts:

    - name: Display the gathered facts
      ansible.builtin.debug:
        var: ansible_chocolatey

    - name: Create a directory for the Chocolatey cache
      ansible.windows.win_file:
        path: C:\ChocoCache
        state: directory

    - name: Configure Chocolatey to use the new cache directory
      chocolatey.chocolatey.win_chocolatey_config:
        name: cacheLocation
        state: present
        value: C:\ChocoCache

    - name: Change the execution timeout
      chocolatey.chocolatey.win_chocolatey_config:
        name: commandExecutionTimeoutSeconds
        state: present
        value: 3600

    - name: Gather facts after reconfiguring Chocolatey
      chocolatey.chocolatey.win_chocolatey_facts:

    - name: Display the new configuration
      ansible.builtin.debug:
        var: ansible_chocolatey.config
----

Commit and push, sync the project, and run *Chocolatey - Facts and configuration* again. The last debug task should show `cacheLocation` as `C:\ChocoCache` and `commandExecutionTimeoutSeconds` as `3600`.

image::8-chocolatey-configuration-job-run-2-successful.png[Updated Chocolatey configuration,link=self,window=_blank]

The same collection also includes `win_chocolatey_source` and `win_chocolatey_feature` for package sources and client features.
